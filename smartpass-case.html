SmartPass is a technological solution designed to efficiently and securely manage and optimize access to spaces. Its approach integrates physical and digital credentials with advanced technologies — facial recognition, QR codes, and other access control methods.

The system centralizes permissions management, ensuring a streamlined and secure workflow. Its flexibility allows it to adapt to different operational contexts.

Flow & Roles
Four levels.
One accreditation.

Event management is divided into four levels: the Super Admin creates the event and assigns the Administrator (responsible for the organization), who validates participants and coordinates physical credentials. The Administrator can delegate tasks to various Managers, responsible for uploading and sending data for specific groups of people for final approval. Finally, the Accredited Participant is the end user who registers, uploads their profile picture, and receives the physical credential to access the venue.

Key Design Decisions
Decision 01
Four-role hierarchy, not flat access
Modeling Super Admin → Admin → Manager → Accredited as a real chain of delegation matched how event teams actually operate, instead of forcing every task onto one admin.
Decision 02
CSV import over manual entry
Events like Paraguay vs Chile need 2,000 accreditations at once. A documented CSV template with an "Ejemplo CSV" download made bulk upload the default path, not an edge case.
Decision 03
QR activation delayed until near event day
Credentials generate immediately but activate only hours before the event — a security decision communicated proactively by email so it never reads as a bug.
Decision 04
Explicit empty and error states everywhere
No blank screens. Every zero-data state ("Aún no tienes lista de gestores") tells the admin exactly what to do next.
Decision 05
Photo upload as a separate, delegable step
Accredited users can be registered without a photo up front; a dedicated task/email closes the loop only when biometric access is required.
Decision 06
Live counters on every event card
Total / accepted / rejected accreditations sit at the top of the dashboard, always visible — no digging into reports to know event readiness.
Learnings
Learning 01
Roles are a design problem, not just permissions
Mapping who does what — Super Admin, Admin, Manager, Accredited — before touching a screen prevented a flat, confusing permission model later.
Learning 02
Bulk operations need their own UX
Designing for 2,000 accreditations at once — not 20 — meant CSV import, filters and empty states had to be first-class, not afterthoughts.
Learning 03
Security decisions need a UX explanation
Delaying QR activation is correct for security, but only works if the email flow tells the user why — otherwise it reads as broken.
The core principle
"Access control should feel invisible when it works — and obvious when it doesn't."
SmartPass had one month from discovery to launch. Every screen had to earn its place: no decorative flows, no ambiguous states — just a clear path from Super Admin configuration to a fan walking into Estadio Defensores del Chaco.
