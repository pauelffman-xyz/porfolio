Process · Vibe Coded, Start to Finish
Speed as the constraint
Clarity as the output
No time for a deck. Only time for the mechanism.

Vibe coding doesn't leave room for exploration — it forces sequencing. The loop had to work before the interface existed. Here's how it actually broke down.

Stage 01
Framing the problem
Chose AI Customer Success because response speed is retention, not a feature on a backlog. The brief: an agent a business can trust with real customers, on day one.
Stage 02
The loop, before any UI
Designed the ask → answer → teach → memorize cycle first, as a state machine. If the loop didn't hold, no interface would save it.
Stage 03
WhatsApp as the only channel
No new app to download, no dashboard to log into. Hugo meets the customer exactly where they already are.
Stage 04
Editable memory
Gave the business owner a direct way to correct Hugo mid-conversation, in plain language — no prompt engineering required.
Stage 05
A live demo, not a pitch deck
Recorded a 60-second demo of the real product answering real questions. A working loop is a stronger pitch than any slide.
Core Mechanic · The Learning Loop
"Evals is our moat."

Hugo isn't smart because of a bigger model — it's useful because every correction becomes permanent memory. The product's real asset isn't the answer engine, it's the loop that keeps improving it.

Step 01
Customer asks a question
Straight on WhatsApp, in their own words. No ticket, no form, no waiting for business hours.
Step 02
Hugo answers
Using the business's existing memory — real data, not a generic script.
Step 03
If Hugo doesn't know, it asks the owner
Instead of guessing or stalling, Hugo escalates the gap directly and honestly.
Step 04
Owner corrects / teaches Hugo
In plain language — typed in the backoffice chat, or spoken directly to Hugo on a live call. No prompt engineering either way.
Step 05
Hugo memorizes and improves
The correction becomes part of permanent memory, not a one-off patch.
Step 06
That knowledge becomes the system
Every future customer conversation benefits from what was just taught.
The core principle
"Each company trains its own Hugo. We train the ecosystem."
Every conversation is a chance to learn, and every correction makes every Hugo better — not just the one that was corrected. That compounding loop, not the model underneath, is the actual moat.

Beyond the Demo · GTM & Business Model
Started with tickets.
Built to scale past them.

Learnings
Learning 01
Constraints are a design tool
Vibe coding forced the loop to be designed before the interface — and the product was better for it.
Learning 02
Ship the mechanism, not the mockup
A working WhatsApp chat beat a polished dashboard nobody could actually click through.
Learning 03
Memory is the real product
The UI is disposable. What compounds — and what's defensible — is what Hugo remembers about each business.
